# 世界书导入格式说明（含 JSON 模板）

> 更新时间：2026-10-11　|　工程：`D:\WorkSpace\Project\YuNian`（分支 `dev-mulai`）
> 配套模板文件：`docs/person-mulai-docs/世界书导入模板.json`
> 相关代码：`feature/settings/.../worldbook/WorldbookTransfer.kt`、`core/agent/.../worldbook/WorldbookJsonCodec.kt`

---

## 一、怎么导入

设置 → 世界书 → **导入**，选择 `.json` 文件即可。导入侧只做两件事：
读取文件为 **UTF-8** 文本 → 交给 `WorldbookTransfer.parseAny(text)` **自动识别格式**。

导入成功的最低要求：

1. 顶层 **`name`** 不能为空（留空时 ST 路径会回落为「导入的世界书」）；
2. **`entries`** 至少有一条。

> 导入入口的文件选择器接受 `*/*`，所以扩展名不是 `.json` 也能选，但内容必须是合法 JSON。

---

## 二、支持两种格式（自动识别）

`parseAny` 按下列顺序判定，**无需在文件里声明用哪种**：

| 判定条件 | 识别为 |
|---|---|
| `entries` 是 **对象（map）** `{ "<uid>": {...} }` | **ST World Info JSON**（推荐） |
| `entries` 是**数组**，且首元素含 `keys` 或 `insertion_order` | ST 数组变体 |
| 顶层有 `scan_depth` 或 `token_budget` | ST 格式 |
| 顶层 `format` == `"lianyu-worldbook"` | **旧 lianyu 格式**（见 §5） |
| 其余 | 旧 lianyu 格式 |

> ⚠️ **强烈推荐用 map 格式**（模板即为此格式）。原因见 §6。

## 三、ST 格式字段表（推荐格式）

### 顶层字段

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `name` | string | 是 | — | 世界书名称；为空则显示「导入的世界书」 |
| `description` | string | 否 | `""` | 说明 |
| `scan_depth` | number | 否 | 10 | 默认扫描深度（条目未单独指定时用） |
| `token_budget` | number | 否 | 10000 | 注入预算（≈ 10000 token，本地 20000 字符） |
| `_createdAt` | number | 否 | 0 | 创建时间戳（本应用自有字段，SillyTavern 忽略） |
| `entries` | **object** | 是 | — | 条目表，key 是 uid（字符串），value 是单条目对象 |

### 单条目字段（`entries` 的值）

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `id` | number | 取 map 的 key | 条目 id；缺省时用 map 键 |
| `keys` | string[] | `[]` | **主关键词**。命中任一即触发（`constant=true` 时不看它） |
| `secondary_keys` | string[] | `[]` | 次级关键词；本应用导出恒为 `[]` |
| `content` | string | `""` | **要注入的正文** |
| `enabled` | bool | `true` | 是否启用。**务必显式写出**，否则 Rust 侧默认 true，禁用条目会意外生效 |
| `insertion_order` | number | 0 | 注入顺序，**升序 = 越先注入**（数字越小越靠前） |
| `case_sensitive` | bool | `false` | 关键词是否区分大小写 |
| `use_regex` | bool | `false` | 关键词是否按**正则**解释 |
| `constant` | bool | `false` | `true` = 恒定注入，不受 `token_budget` 裁剪、不依赖关键词命中 |
| `position` | string | `at_depth` | 注入位置，见下表（5 值） |
| `role` | string | `system` | 注入消息角色：`system` / `user` / `assistant` |
| `scan_depth` | number | 10 | 条目级扫描深度（覆盖顶层） |
| `depth` | number | 4 | **仅 `position=at_depth` 时有效**，注入到倒数第 N 条消息处 |
| `extensions` | object | — | 本应用自有扩展字段，见 §4 |

#### `position` 取值（5 值，全支持）

| 值 | 含义 |
|---|---|
| `before_char` | 角色定义**之前** |
| `after_char` | 角色定义**之后** |
| `top_of_chat` | 对话**顶部** |
| `bottom_of_chat` | 对话**底部** |
| `at_depth` | 按 `depth` 注入到**倒数第 N 条**消息处 |

> 未知/缺省值回落到 `at_depth`。

---

## 四、`extensions` 扩展字段（本应用自有，SillyTavern 会忽略）

导出时会写入，导入时读取以**无损还原**编辑器状态；手工编写时全部可选。

| 字段 | 说明 |
|---|---|
| `_bookId` / `_bookName` | 来源书本（迁移/合并时回溯用） |
| `_sortOrder` | UI 拖拽排序位 |
| `_priority` | 摘要优先级。**建议写上**——不写时会由 `insertion_order` 反推成很大的数 |
| `_createdAt` / `_updatedAt` | 时间戳，用于同 `_sortOrder` 下的稳定次序 |

### ★ `priority` 与 `insertion_order` 的关系

本地「优先级」与 ST 的 `insertion_order` 是**取反**关系：

```
insertion_order = 4,294,967,296 (2^32) - priority
```

即 **本地优先级越大 → `insertion_order` 越小 → 越先注入**。

- 手工写模板时，最简单的做法是直接给 `insertion_order` 排 `1, 2, 3, ...`（越小越先注入）；
- 若你更想用「优先级」的直觉，就写 `extensions._priority`（越大越优先），导入侧会优先采用它。

## 五、旧 lianyu 格式（保留兼容，不推荐新写）

`entries` 是**数组**的旧格式，结构如下：

```json
{
  "format": "lianyu-worldbook",
  "version": 1,
  "name": "示例世界书",
  "description": "",
  "entries": [
    {
      "keywords": ["小袁"],
      "content": "……",
      "injectionPosition": "AFTER_SYSTEM_PROMPT",
      "role": "SYSTEM",
      "priority": 0,
      "injectDepth": null,
      "scanDepth": 10,
      "caseSensitive": false,
      "useRegex": false,
      "constantActive": false,
      "enabled": true,
      "sortOrder": 0
    }
  ]
}
```

- `injectionPosition` 取值：`BEFORE_SYSTEM_PROMPT` / `AFTER_SYSTEM_PROMPT` / `TOP_OF_CHAT` / `BOTTOM_OF_CHAT` / `AT_DEPTH`
- `role` 取值：`SYSTEM` / `USER` / `ASSISTANT`
- 该格式**必须**有非空 `name` 与非空 `entries`。
- 当前导出**不再产出**此格式（导出走 ST 格式），它仅用于兼容历史文件。

---

## 六、为什么推荐 map 格式（重要）

Rust 引擎 `Lorebook::parse()`（`agent-native/src/lorebook.rs`）**只在 `entries` 为数组时**才走 `chara_card` 格式校验，而 `chara_card 0.4.1` 的条目 `position` 枚举**只认 2 个值**（`before_char` / `after_char`）：

- 数组模式下，`top_of_chat` / `bottom_of_chat` / `at_depth` 会**校验失败**；
- 同时它不认识 `depth` / `role` / `scan_depth` 这些字段，会**静默丢失**。

而 **map 格式**（`entries` 为对象）绕过 `chara_card` 校验，直接落到自研条目结构，**5 值 `position` 与全部字段都支持**。

> 顺序问题：map 的迭代顺序 Rust 侧不保证，因此引擎在注入前会按 `insertion_order` **显式重排**——只要 `insertion_order` 唯一，最终顺序就是确定的。手工编写时请保证各条目的 `insertion_order` 互不相同。

---

## 七、快速上手清单

1. 复制 `世界书导入模板.json`；
2. 改 `name`；
3. 按需增删 `entries` 里的条目，`entries` 保持**对象**形态（key 尽量用字符串数字）；
4. 每条要**显式**写 `enabled`；
5. 保证各行 `insertion_order` 唯一；
6. 需要「永远生效」的设定就把 `constant` 设为 `true`；
7. 保存为 UTF-8 的 `.json`，在设置页导入。
