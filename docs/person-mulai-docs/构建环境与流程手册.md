### 关键配置文件

- **环境变量**（用户级已持久化）：`JAVA_HOME=D:\dev\jdk17`、`ANDROID_HOME`/`ANDROID_SDK_ROOT=D:\Android\Sdk`、`ANDROID_NDK_HOME=D:\Android\Sdk\ndk\30.0.14904198`；PATH 已加 `D:\dev\jdk17\bin`、`D:\Android\Sdk\platform-tools`、`D:\dev\rust\cargo\bin`
- **用户级 Gradle 配置** `C:\Users\yszsu\.gradle\gradle.properties`（优先级高于仓库文件，不进 Git）：
  - `org.gradle.java.home=D:\dev\jdk17`
  - `org.gradle.java.installations.paths=D:\dev\jdk17,D:\dev\jdk21` ← **必须用逗号分隔，分号会构建失败**
  - `YUNIAN_STORE_PASSWORD` / `YUNIAN_KEY_PASSWORD` / `YUNIAN_KEY_ALIAS=yunian`（签名口令）
- **工程 `local.properties`**：`sdk.dir`（在 .gitignore 中）
- **Rust 镜像** `D:\dev\rust\cargo\config.toml`：crates.io → rsproxy.cn；rustup 用 `RUSTUP_DIST_SERVER=https://rsproxy.cn`

### 签名

- `D:\WorkSpace\Project\YuNian\release.keystore`：2026-10-09 生成（RSA 2048，有效期 30 年，别名 `yunian`，口令在用户级 gradle.properties）
- **debug 包也用 release 签名**（加固壳的 DEX 解密密钥绑定签名证书，设计如此）
- ⚠️ keystore 是全部后续版本的唯一签名凭证，**务必备份**（丢了无法给老用户发升级）

### 已打的两个"补丁"（重要，会失效需重打）

1. **dlltool shim**：`D:\dev\rust\cargo\bin\dlltool.exe` = NDK 的 `llvm-dlltool.exe` 复制件。GNU 宿主工具链编译 build script 依赖时需要它（CLI 完全兼容）。删了就重拷：
   ```
   copy D:\Android\Sdk\ndk\30.0.14904198\toolchains\llvm\prebuilt\windows-x86_64\bin\llvm-dlltool.exe D:\dev\rust\cargo\bin\dlltool.exe
   ```
2. **rustix 1.1.4 build.rs 容错补丁**：位于 `D:\dev\rust\cargo\registry\src\rsproxy.cn-*/rustix-1.1.4/build.rs`。原代码 spawn rustc 写 stdin 管道在本机报 `ERROR_PIPE_BUSY(231)`，已改成失败时保守回退。**执行 `cargo update` 或重装依赖会还原补丁**——再报 rustix 构建脚本 panic/unwrap 失败时按此重打（把 build.rs 末尾 `test_fn` 探测函数里的 `.unwrap()` 链改成容错返回 false）。

## 二、构建流程（每次发新包照此执行）

### 第 0 步：判断要不要重编 Rust so

对比时间戳：`agent-native/src/agent.rs`（或 agent-native 下任何 .rs）晚于 `core/agent/src/main/jniLibs/arm64-v8a/liblianyu_agent.so` → **需要重编**；否则跳到第 2 步。

```bash
cd D:/WorkSpace/Project/YuNian
stat -c "%y" agent-native/src/agent.rs core/agent/src/main/jniLibs/arm64-v8a/liblianyu_agent.so
```

> ⚠️ 不重编的后果：APK 会打进旧 Rust 代码，功能不同步。

### 第 1 步：重编 Rust so（仅当 Rust 代码有改动）

```bash
cd D:/WorkSpace/Project/YuNian/agent-native
export RUSTUP_HOME="D:\\dev\\rust\\rustup" CARGO_HOME="D:\\dev\\rust\\cargo" \
       ANDROID_NDK_HOME="D:\\Android\\Sdk\\ndk\\30.0.14904198" \
       PATH="/d/dev/rust/cargo/bin:$PATH"
cargo ndk -t arm64-v8a -t armeabi-v7a -t x86_64 -t x86 \
  -o ../core/agent/src/main/jniLibs build --release
```

- 正常耗时 2 分钟左右，成功后 so 时间戳更新
- **不要用 `scripts/build_agent.ps1`**：脚本是 UTF-8 无 BOM，Windows PowerShell 5.1 按 ANSI 解析中文注释直接语法报错；上面命令就是它的等价形式
- 如遇 rustix 构建脚本报错 → 见上文"补丁 2"

### 第 2 步：打 APK

```bash
cd D:/WorkSpace/Project/YuNian
export JAVA_HOME="D:\\dev\\jdk21" PATH="/d/dev/jdk21/bin:$PATH"
./gradlew assembleDebug --console=plain
```

- 增量构建 1~3 分钟，首次/大改 6~15 分钟
- 产物：`app/build/outputs/apk/debug/app-debug.apk`（**默认就只含 arm64-v8a**，`abiFilters` 写死）

### 第 3 步：验证 + 归档

```bash
# 验证版本号和 ABI
D:/Android/Sdk/build-tools/35.0.0/aapt.exe dump badging \
  app/build/outputs/apk/debug/app-debug.apk | head -1
# 应看到 versionCode='28' versionName='2.1.1'（以当前版本为准）

# 复制到工作区归档
cp app/build/outputs/apk/debug/app-debug.apk \
   "D:/WorkSpace/WorkBuddy/YuNian/outputs/YuNian-debug-arm64-v8a-<版本号>.apk"
```

### 版本号升级（发新版本时）

改 `app/build.gradle.kts` 第 16-17 行：`versionCode` +1（整数）、`versionName`（如 2.1.1 → 2.1.2），然后走上面流程。

## 四、常见问题速查

| 症状 | 原因 | 解决 |
|---|---|---|
| 构建开头就失败，提示 installations paths | 用户级 gradle.properties 用了分号 | 改成逗号分隔 |
| Gradle daemon 报需要 Java 21 | 守护进程锁定 toolchain 21 | 已本地预装 `D:\dev\jdk21`，自动发现；确保 `installations.paths` 含它 |
| 链接期 `os error 193` / 找不到 link.exe | 之前 MSVC 工具链的问题 | 已整体切 GNU 工具链，不会再遇 |
| rustix build script panic（管道 231） | 沙箱管道限制 | 见"补丁 2"，重打后 `rm -rf target/release/build/rustix-*` 再编 |
| cargo 找不到 rustc / 0 字节 shim | rustup 代理损坏 | 把 `D:\dev\rust\cargo\bin\rustup.exe` 复制为同目录 `rustc.exe`、`cargo.exe` |
| 签名失败要求 release.keystore | debug 也走 release 签名 | keystore 已就位，口令在用户级 gradle.properties |
| 下载依赖慢 | — | JDK/SDK 用华为云、Rust 用 rsproxy、GitHub 资源加 `gh-proxy.com` 前缀 |
