> 更新时间：2026-10-11　|　工程：`D:\WorkSpace\Project\YuNian`（分支 `dev-mulai`）
> 对应界面：**设置 → 插件设置 → 通用插件**（Tab 索引 1；索引 0 是「消息通道」）

本文档回答三个问题：**通用插件 Tab 里有哪些条目**、**每条显示什么文案**、**它是干什么用的**。

---

## 一、分类规则（谁进这个 Tab）

分类**只按插件类型 `PluginKind` 归，不按插件 id 写死清单**
（见 `feature/settings/.../plugin/PluginSettingsBoard.kt` 的 `categoryOf`）：

| `PluginKind` | 归属 Tab |
|---|---|
| `ADAPTER` | 消息通道 |
| `TOOL` / `SKILL` / `STICKER` / `PIPELINE` | **通用插件** |

也就是说，「通用插件」= **除消息通道适配器之外的一切插件**（工具、技能、表情包、管道）。
这条规则同时覆盖现在和**将来**新增的插件——新加一个 TOOL 插件会自动出现在这里，不需要改任何清单。

> 补充：`PIPELINE`（管道，回合后处理逻辑）没有独立的用户界面概念，按裁定「cordis 万物皆是插件」一并归入通用插件。

## 三、逐条说明：它是什么、停用后会怎样

### 1.「工具授权」（保留条目，`tool.grant`）

- **它不是一个插件**，而是并入通用插件分类的一个**固定入口**（用户裁定 Q2/Q6），因此**没有开关**。
- 点进去是「Agent 工具的能力授权清单」，管理那些**执行前需要用户确认**的工具能力。
- 说明为什么 id 用 `tool.` 前缀而非 `capability.`：它的内容是「Agent 工具的授权」，与 `tool` 语义对齐，也避免和 `skill.builtin_chat_protocol` 这类真实插件 id 前缀混淆。
- 注意：`tool.grant` 位于**插件 id 的取值域内**。若将来真有插件注册成同名 id，保留条目会让位给真实插件（真实插件优先），不会出现两行同名。

### 2. 自动化工具（`automation.core`，TOOL）

- **作用**：向工具注册表注册 5 个工具，让 AI 能自己安排「以后做某事」——
  `automation_create`（创建定时任务）、`automation_create_workflow`（创建工作流）、
  `automation_fire`（立即触发）、`automation_list`（列出）、`automation_cancel`（取消）。
- **停用后**：这 5 个工具立即从注册表摘除，AI 无法再创建/触发任何定时任务。
- **边界**：调度层（`AutomationScheduler` / `AutomationFireWorker` / `AutomationTickProviderImpl`）**不在本插件范围内**——定时器由 Kotlin 侧持有（Rust 无定时器），本插件只管「工具能不能被调用」。

### 3. 第一人称思考（`chat.first_person_reasoning`，PIPELINE）

- **作用**：改变模型思考过程的**人称与风格**——用角色本人的第一人称（内心独白），而不是英文第三人称任务规划。
- **实现要点**：这是一个**管道插件**，装载即注入、卸载即不注入。组装侧（`ChatGenerationManager.serializeHistoryJson`）每次组 history 时读这个开关，关闭时 messages 逐字节不变（不注入任何东西）。
- **停用后**：模型的思考退回默认的英文第三人称任务规划风格。
- **无依赖**（`requires` 为空）。

### 4. 消息发送（`message.send`，TOOL）

- **作用**：注册唯一一个工具 `send_channel_message`，让 AI 把一条消息**经指定通道发出**。
- **它只做「发起方」，不认识任何具体通道**：不 import QQ、不 import 微信、不持有适配器；具体派发由各通道插件（`channel.qqbot` / `channel.wechat`）认领。
- **两个关键属性**（不是修饰语，是装配事实）：
  - `requiresConfirmation = true` —— 发送前需要用户确认；
  - `appLocalOnly = true` —— 只在 App 内会话可见（渠道隔离）。
- **停用后**：AI 无法主动发消息。
- **为什么发起方是独立插件**：这样「可自由启用/停用通道」才有正确语义——通道停用时，本工具仍在注册表里，但派发该通道会**没人认领**，于是返回「该通道未启用」的**明确失败**，用户能分清「没启用通道」和「工具坏了」。

### 5. 内置聊天工具协议技能（`skill.builtin_chat_protocol`，SKILL）

- **作用**：幂等写入内置技能 `builtin_chat_tool_protocol`——它是**微信聊天红线 + 气泡工具协议**，规定 AI **何时改用工具输出**（`emit_bubble` / `emit_segmented` / `send_sticker`）。
- **影响面**：直接决定回复的**气泡分段与节奏**。
- **停用后**：技能不写入，AI 退回**普通文本回复**（不再分段、不再走气泡/表情工具）。
- **依赖**：`appContext`。装载必须发生在初始化（`markInitialized`）之前。

### 6. 表情包偏好引擎（`sticker.preference`，STICKER）

- **作用**：接线表情包目录的**文件系统变更钩子**并做首启全量同步（文件系统 → 表情包库 → 偏好引擎），引擎据此决定 AI **该挑哪张表情包**发。
- **停用后**：引擎不再更新，AI 的表情包挑选随之失效。
- **依赖**：`appContext`。同样必须在 `markInitialized` 之前装载。

### 7. 无障碍自动化（`ui.assists`，TOOL）

- **作用**：注册 9 个工具，让 AI **看着屏幕操作手机**：
  - 读屏 = `screen_read` / `screen_dump_ui`
  - 点击 = `screen_tap` / `screen_click_text`
  - 滑动 = `screen_swipe`
  - 输入 = `screen_input_text`
  - 导航与状态 = `accessibility_status` / `press_back` / `go_home`
- **停用后**：AI **立即**失去这些能力（每个工具都配了 `ctx.effect` 注销副作用，卸载即摘除，不存在「插件停了、工具还挂着」的僵尸窗口）。
- **依赖**：`tools`。

## 四、开关含义（怎么读这些开关）

- **ON 当且仅当插件已被宿主装载**。开关只表达**运行态**，持久化意图不能覆盖运行态：
  - 保存失败或卸载失败时，仍在运行的插件**必须保持 ON**；
  - 未装载的插件，无论存储里写的是什么，都**必须 OFF**。
- 保存失败时，切换事务会单独提示「当前生效但未保存，重启可能恢复」。
- 列表**不因未装载而消失**——停用的插件仍然列出，否则用户没法把它重新打开。

## 五、不在本 Tab 的插件（对照）

以下两个是「消息通道」Tab 的条目（类型 `ADAPTER`），列出仅为对照：

| 插件 id | 显示名 | 描述文案 |
|---|---|---|
| `channel.qqbot` | QQ 机器人通道 | 通过 QQ 机器人收发消息，并支持按请求主动发送；停用后不再收发。 |
| `channel.wechat` | 微信通道 | 通过微信收发消息，并按请求主动发送给绑定用户；停用后不再收发。 |

> 另有 `ChatToolLifecyclePlugin`（把工具执行状态投影成会话里的工具卡片）：它**不在蓝图里、也不出现在设置页**——它由聊天侧**按回合**注册/卸载（见 `ChatGenerationManager`），属于内部装配件，不作为可配置插件暴露。
